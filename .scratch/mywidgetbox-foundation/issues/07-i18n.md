# 07: 語言（正體中文與英文）

Status: resolved
Blocked by: 01

**What to build:** 把介面文字集中為以 key 取用的訊息表，提供 `zh-Hant` 與 `en`；新增語言只需加一份訊息表。語言決定順序：`?lang=` > 使用者手動選擇（已記住） > `navigator.language`（中文系 → `zh-Hant`，其他 → `en`）。目錄頁與骰子皆套用。

- [x] 目錄頁與骰子所有文字來自訊息表，無寫死字串
- [x] 語言切換器，選擇會被記住
- [x] `?lang=` 強制指定語言，可被 Share link 帶上
- [x] 測試：語言決定順序的各種組合；缺少翻譯 key 時有可預期的後備

## Answer

- `shared/i18n.ts` (opt-in, headless): `createI18n(env, messageTables, { browserLanguage })` resolves the locale `?lang=` > stored manual choice (`mywidgetbox:lang` via `env.storage`) > browser language (matched by primary subtag, so any `zh-*` -> `zh-Hant`) > `en`; unsupported values fall through. `t(key, params)` falls back current locale -> `en` -> the key, with `{name}` placeholders.
- `shared/i18n-dom.ts`: `bindStaticText` fills `data-i18n` / `data-i18n-aria-label` elements and `<html lang>`, re-rendering on change; `mountLanguageSwitcher` adds a `<select>` that remembers the choice.
- Catalog page (`index.html` + new root `main.ts`/`messages.ts`) and dice (`dice/messages.ts`) now take all text from message tables and show the switcher.
- `?lang=` is exported as `LANG_PARAM` for the Share link ticket (05) to append; it is never written to storage.
- Tests: `shared/i18n.test.ts` (resolution order combinations, persistence across reload, fallback, placeholders). Switcher + persistence smoke-tested in a browser via `vite preview`.
