# 全站 Theme 與首頁改版

Status: resolved

## 意圖與原因

使用者覺得目前的網站「陽春」：首頁只有標題加三個文字連結，設定面板全部是瀏覽器原生、未加樣式的控制元件。他要的是「精簡，但不陽春」。

網站有兩種用途：
- 放進 OBS 時，多半只用 **Widget 本體**（Display mode）。
- 把網址介紹給別人時，**首頁與設定面板**的觀感很重要。

因此這次只改「給人操作的部分」的外觀。Widget 本體之前已經調整過，**不動**。

在 visual companion 比較了三種風格。它們的版面相同，只有色調不同，所以使用者決定做成**可切換的 theme**，讓使用者自己選。

## 目標

1. 加入全站 theme 機制，並提供三套 theme：
   - **柔和卡片（soft）**：預設。淺灰底、白色圓角卡片、淡陰影，單一青綠強調色（約 `#2f7d6d`），整體乾淨，像現代 App。
   - **深色工作室（dark）**：深灰底（約 `#121417`），強調色為琥珀色（約 `#f0a63a`），像串流軟體的控制台。
   - **溫暖紙本（paper）**：米白紙色（約 `#f6f1e7`），標題用襯線字體，以細線分隔，點綴色為磚紅（約 `#b5482f`），像桌遊說明書。
   - 參考 mockup：`.superpowers/brainstorm/1745-1793543505/content/visual-style.html`。色值可微調，但三套的性格要保持。
2. 加入 theme 切換選單：
   - 放在語言選單旁邊，首頁和三個 Widget 頁面都要有。
   - 選擇記在瀏覽器裡（localStorage），全站共用，做法比照語言選擇的 `mywidgetbox:lang`。
3. 首頁改版，目標是讓人「一眼看懂有哪些工具，點進去就好」：
   - 上方：標題「MyWidgetBox」，下面一行簡短說明（中英文），例如「給直播和桌遊用的小工具，可直接放進 OBS」。右上角放語言選單和 theme 選單。
   - 主體：三張並排卡片，順序為骰子、轉盤、計時器。每張卡片有一個線條圖示、Widget 名稱和一句很短的用途說明，整張卡片都可以點擊。
   - 窄螢幕時三張卡片改成上下排列。
   - 圖示自己畫成線條 SVG，用 `currentColor` 跟著 theme 變色，不用 emoji（emoji 在各作業系統長得不同，也無法跟著 theme 變色）。
4. 設定面板（三個 Widget 頁）的外觀換成自訂樣式，並跟著 theme 走：
   - 控制元件全部重新設計樣式：按鈕、文字輸入框、數字輸入框、`select`、勾選框、拉桿（range）、顏色選擇（color），以及檔案選擇按鈕。
   - 區塊標題（h2，例如「選項」「音效」「外觀」）改成小字加字距的分段標題，區塊之間用細線或間距分隔。
   - 主要動作按鈕使用強調色：轉盤的「轉動」、骰子的擲骰、計時器的開始，以及「複製 Share link」。其他按鈕用一般樣式。
   - 也要套用 theme 的部分：Widget 旁邊不會進 OBS 的按鈕（如「轉動」「重置」）、面板收合把手、語言列與首頁連結。

## 非目標

- 不改 Widget 本體的外觀：骰子、轉盤、計時器數字，以及它們的 Appearance 設定（背景、字型、顏色等）。
- 不改設定面板的版面、區塊順序、收合行為和功能。這次只換外觀。
- 首頁不放教學、OBS 設定說明或預覽動畫。
- theme 不寫進 Settings、Preset 或 Share link。它是瀏覽器端的個人偏好，和語言選擇一樣。
- 不做「跟隨系統深色模式」的自動切換（使用者沒有要求）。

## 反目標（做了反而算失敗）

- Display mode 或 OBS 裡的畫面因為 theme 而有任何改變。
- 頁面載入時先閃一下預設 theme，再跳成使用者選的 theme（FOUC）。
- 控制元件換了樣式之後變得難用：觸控尺寸變小、鍵盤焦點看不到、對比不足、拉桿數值看不到等。
- 某個 theme 下有元件沒套到，仍是原生樣式或顏色不協調。三套 theme 都要從頭到尾檢查過。

## 限制

- 必須在 Chromium 運作，包含 OBS Browser Source。
- 沿用現有技術：Vite、TypeScript、純 CSS，不引入 CSS 框架或 UI 套件。
- 依 ADR-0002，各 Widget 在技術上互相獨立，共用的部分是 opt-in 的 `shared/`。theme 機制放在 `shared/`。
- beta 之前不寫 Settings migration。theme 是新的獨立 key，沒有 migration 問題。
- 既有 UI 規則維持不變：每個拉桿旁邊顯示數值；各區塊的順序依主題重要性排列。
- 介面文字兩種語言（en、zh-Hant）都要提供。程式碼、註解和 commit 用英文。

## 使用者已決定的做法

- 三套 theme 版面相同，只差色調和字體。
- 由使用者切換，記在瀏覽器，預設是柔和卡片。
- 切換選單放在語言選單旁邊。
- 首頁採用三張卡片、線條圖示和一句說明的設計。
- 只換外觀，不改面板的版面和功能。

## Theme 的作用範圍（由實作者審閱時提出，依非目標推定，屬於我的判斷）

- **頁面底色歸 Appearance 管**：Widget 頁的 stage 區域（Widget 所在的那一側）繼續顯示 Appearance 的背景設定，這樣編輯時看到的就是 OBS 裡會出現的樣子。theme 只管面板、語言列和不會進 OBS 的按鈕。用 dark theme 時，深色面板會接在白色（或使用者自訂）的 stage 旁邊，這是預期的結果。首頁沒有 Appearance 設定，整頁由 theme 管。
- **theme 字體不能滲進 Widget**：paper 的襯線字體只套在面板、首頁和語言列，不設在 `body` 上。Appearance 字型設為預設（`''`）時，Widget 文字的字體要和改版前相同。
- **Display mode 完全不受 theme 影響**：控制元件的樣式要限定在面板、`[data-controls]` 和首頁的範圍內，不寫全域的 `button {}`、`input {}`，以免碰到 Widget 本體裡的 `<button>`（例如 `#die`、`#wheel`、`#result`）。驗收時，Display mode 的畫面要和改版前一致（截圖比對）。
- **寬螢幕時疊在使用者背景上的按鈕**：例如「轉動」「重置」，按鈕本身使用不透明的 theme 底色和邊框，以確保在圖片或透明背景上看得清楚。不另外加底板。

## 留給實作者決定的部分

- theme 的實作方式。建議做法：在 `html` 上設 `data-theme`，用 CSS custom properties 定義色彩、圓角、字體等 token，元件樣式只引用 token。
- 防止 FOUC 的做法。例如在每個頁面的 `<head>` 放一小段同步 inline script，在第一次繪製前讀出 localStorage 並設定 `data-theme`（module script 是 deferred 的，等它執行時已經太晚）。
- 各 token 的確切數值、陰影和 focus ring 的樣式。
- 拉桿、勾選框、`select` 的自訂樣式寫法。可使用 `appearance: none`、`accent-color` 等，只要在 Chromium 表現一致即可。
- 三個線條圖示的具體造型：骰子、轉盤、計時器各一個，風格一致即可。
- 首頁說明文字與各卡片用途說明的確切措辭（中英文）。

## 驗收方式

- 首頁和三個 Widget 頁，在三套 theme × 寬窄兩種螢幕下各截圖檢查：沒有遺漏原生樣式、文字對比足夠、版面沒有溢出。
- 切換 theme 後重新整理，theme 保持不變，也不會閃爍。
- 開啟 `?display=1`（以及透明背景）的 Share link 時，畫面和改版前完全一樣。
- 型別檢查、lint、測試和 build 都通過。
